## 📊 系统分层

### 1. 表现层（Presentation Layer）

**微信小程序**

- **职责**：用户交互界面
- **技术**：微信小程序原生开发
- **主要页面**：
  - 首页：轮播图、门店推荐
  - 门店列表：搜索、筛选
  - 门店详情：房间列表、预订
  - 订单管理：订单列表、详情
  - 个人中心：用户信息、钱包

### 2. 应用层（Application Layer）

**Spring Boot 后端**

#### Controller 层
- **职责**：接收请求，参数验证，调用 Service
- **规范**：RESTful API 设计
- **主要控制器**：
  - `UserController`：用户相关接口
  - `StoreController`：门店相关接口
  - `OrderController`：订单相关接口
  - `PaymentController`：支付相关接口
  - `DeviceController`：设备控制接口

#### Service 层
- **职责**：业务逻辑处理
- **特点**：事务管理、业务校验
- **主要服务**：
  - `UserService`：用户管理
  - `OrderService`：订单处理
  - `PaymentService`：支付处理
  - `WechatService`：微信接口封装
  - `DeviceService`：设备控制

#### Repository 层
- **职责**：数据访问
- **技术**：MyBatis Plus
- **主要仓储**：
  - `UserRepository`
  - `OrderRepository`
  - `PaymentRepository`
  - `StoreRepository`
  - `RoomRepository`

### 3. 数据层（Data Layer）

#### MySQL
- **职责**：持久化存储
- **核心表**：
  - `users`：用户表
  - `stores`：门店表
  - `rooms`：房间表
  - `orders`：订单表
  - `payments`：支付记录表
  - `devices`：设备表

#### Redis
- **职责**：缓存和分布式锁
- **使用场景**：
  - 用户会话缓存
  - 房间状态缓存
  - 门店列表缓存
  - 分布式锁（房间预订）

## 🔄 核心业务流程

### 1. 用户登录流程

```
用户打开小程序
    ↓
调用 wx.login() 获取 code
    ↓
发送 code 到后端 /api/auth/login
    ↓
后端调用微信 code2Session 接口
    ↓
获取 openid 和 session_key
    ↓
查询或创建用户记录
    ↓
生成 JWT Token
    ↓
返回 Token 给小程序
    ↓
小程序存储 Token
```

### 2. 预订支付流程

```
用户选择房间和时长
    ↓
创建订单 POST /api/orders
    ↓
后端创建订单记录（状态：待支付）
    ↓
调用微信支付统一下单接口
    ↓
返回支付参数给小程序
    ↓
小程序调用 wx.requestPayment()
    ↓
用户完成支付
    ↓
微信支付回调 POST /api/payment/notify
    ↓
验证签名，更新订单状态
    ↓
发送开门指令到设备
    ↓
返回成功，用户进入房间
```

### 3. 自动计时流程

```
订单开始使用
    ↓
记录开始时间
    ↓
定时任务每分钟检查
    ↓
计算已使用时长
    ↓
更新订单状态
    ↓
时长用完前 5 分钟提醒
    ↓
时长用完自动结束订单
    ↓
发送关门指令到设备
```

## 🔐 安全设计

### 1. 认证授权

- **微信登录**：使用微信官方 code2Session
- **Token 管理**：JWT Token，有效期 7 天
- **权限控制**：基于角色的访问控制（RBAC）

### 2. 数据安全

- **传输加密**：全站 HTTPS
- **敏感信息加密**：用户手机号、支付信息
- **SQL 注入防护**：MyBatis 参数化查询
- **XSS 防护**：输入验证和输出转义

### 3. 支付安全

- **签名验证**：所有支付请求和回调验证签名
- **证书管理**：定期更新微信支付证书
- **幂等性**：支付订单防重复提交
- **金额校验**：前后端双重校验

## 📈 性能优化

### 1. 缓存策略

| 数据类型 | 缓存时间 | 更新策略 |
|---------|---------|---------|
| 门店列表 | 1 小时 | 主动更新 |
| 房间状态 | 5 分钟 | 实时更新 |
| 用户信息 | 30 分钟 | 被动失效 |
| 订单详情 | 10 分钟 | 主动更新 |

### 2. 数据库优化

- **索引设计**：为常用查询字段建立索引
- **分页查询**：列表接口必须分页
- **读写分离**：主从复制（未来扩展）
- **慢查询监控**：记录超过 1 秒的查询

### 3. 接口优化

- **响应压缩**：启用 Gzip 压缩
- **接口限流**：防止恶意请求
- **异步处理**：耗时操作异步执行
- **批量操作**：减少数据库查询次数

---

## 🛡️ 容错设计

### 1. 降级策略

- **支付降级**：支付失败时提供重试机制
- **设备降级**：设备离线时提供人工开门码
- **缓存降级**：Redis 故障时直接查询数据库

### 2. 监控告警

- **业务监控**：订单异常、支付失败
- **系统监控**：CPU、内存、磁盘
- **日志监控**：错误日志实时告警

### 3. 数据备份

- **数据库备份**：每日全量备份
- **日志备份**：保留 30 天日志
- **配置备份**：版本控制管理

## 🚀 部署架构

### 生产环境

```
┌─────────────────────────────────────────┐
│              Nginx (443)                │
│  - SSL 终止                              │
│  - 负载均衡                              │
│  - 静态资源                              │
└────────────┬────────────────────────────┘
             │
    ┌────────┴────────┐
    ↓                 ↓
┌─────────┐      ┌─────────┐
│ Backend │      │ Backend │
│ (8080)  │      │ (8081)  │
└────┬────┘      └────┬────┘
     │                │
     └────────┬───────┘
              ↓
     ┌────────────────┐
     │  MySQL + Redis │
     └────────────────┘
```

### Docker Compose 配置

```yaml
version: '3.8'

services:
  nginx:
    image: nginx:1.21
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf
      - ./ssl:/etc/nginx/ssl
    depends_on:
      - backend

  backend:
    image: easyjoylife-backend:latest
    ports:
      - "8080:8080"
    environment:
      - SPRING_PROFILES_ACTIVE=prod
    depends_on:
      - mysql
      - redis

  mysql:
    image: mysql:8.0
    environment:
      - MYSQL_ROOT_PASSWORD=${MYSQL_ROOT_PASSWORD}
      - MYSQL_DATABASE=easyjoylife
    volumes:
      - mysql-data:/var/lib/mysql

  redis:
    image: redis:6.0
    volumes:
      - redis-data:/data

volumes:
  mysql-data:
  redis-data:
```
