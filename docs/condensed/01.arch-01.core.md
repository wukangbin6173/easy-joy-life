# 核心架构原则（精炼版）

> **来源**：standards/01.arch-01.core.md
> **用途**：快速查阅核心架构原则
> **行数限制**：100-150 行

---

## 🎯 设计哲学

### 1. 微信生态优先
- 小程序作为唯一前端入口
- 微信支付作为唯一支付方式
- 微信用户体系实现快速登录

### 2. 无人值守设计
```
扫码 → 开门 → 计时 → 扣费 → 结算（全自动）
```

### 3. 前后端分离
```
小程序 ←→ Spring Boot API ←→ MySQL + Redis
```

---

## 🏗️ 技术栈

| 层级 | 技术 | 理由 |
|------|------|------|
| 前端 | 微信小程序 | 微信生态集成 |
| 后端 | Spring Boot 2.x | 成熟稳定 |
| 数据库 | MySQL 8.0 | 事务支持 |
| 缓存 | Redis 6.0 | 高性能 |
| 支付 | 微信支付 V3 | 官方推荐 |
| 部署 | Docker Compose | 简化部署 |

---

## 🔐 安全原则

### 认证授权
- 微信 code2Session 登录
- JWT Token（7 天有效期）
- RBAC 权限控制

### 数据安全
- 全站 HTTPS
- 敏感信息加密
- SQL 注入防护

### 支付安全
- 证书定期更新
- 签名验证
- 幂等性保证

---

## 📊 数据设计

### 核心实体关系
```
用户 1:N 订单 1:1 支付记录
门店 1:N 房间 1:N 设备
```

### 状态流转
- 订单：待支付 → 已支付 → 使用中 → 已完成
- 房间：空闲 → 占用中 → 维护中

### 一致性保证
- 事务：订单创建、支付、开门同一事务
- 分布式锁：Redis 实现房间预订锁
- 最终一致：支付回调异步处理

---

## 🚀 性能优化

### 缓存策略
| 数据 | 时间 | 策略 |
|------|------|------|
| 门店列表 | 1h | 主动更新 |
| 房间状态 | 5min | 实时更新 |
| 用户信息 | 30min | 被动失效 |

### 数据库优化
- 索引设计
- 分页查询
- 慢查询监控（>1s）

### 接口优化
- Gzip 压缩
- 接口限流
- 异步处理

---

## 🛡️ 容错设计

### 降级策略
- 支付失败 → 重试机制
- 设备离线 → 人工开门码
- Redis 故障 → 直接查数据库

### 监控告警
- 业务：订单异常、支付失败
- 系统：CPU、内存、磁盘
- 日志：错误日志实时告警

### 数据备份
- 数据库：每日全量备份
- 日志：保留 30 天
- 配置：版本控制

---

## 📏 开发规范

### 代码规范
- 遵循 Java 命名约定
- 关键逻辑必须注释
- 统一异常处理

### 接口规范
- RESTful 风格
- 统一响应格式
- API 版本管理

### 测试规范
- 核心逻辑单元测试
- 关键流程集成测试
- 上线前压力测试
