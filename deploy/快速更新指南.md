# 快速更新指南

## 📋 更新策略

根据修改的内容，选择合适的更新方式：

| 修改内容 | 需要重启的服务 | 使用脚本 |
|---------|--------------|---------|
| **Java代码** | 仅Spring Boot | `update-backend-only.sh` |
| **配置文件** | 仅Spring Boot | `update-backend-only.sh` |
| **Nginx配置** | 仅Nginx | `systemctl reload nginx` |
| **数据库结构** | 无需重启 | 执行SQL脚本 |
| **全新部署** | 所有服务 | `deploy-backend-systemd.sh` |

---

## 🚀 最常用：仅更新Spring Boot应用

### 使用场景
- 修改了Java代码
- 修改了application.yml配置
- 修改了业务逻辑
- 修改了API接口

### 本地操作（推荐）

**步骤1: 上传修改的文件**
```bash
# 如果修改了Java代码
scp backend/src/main/java/com/easyjoylife/xxx.java root@www.quexitai.com:/opt/easy-joy-life/backend/src/main/java/com/easyjoylife/

# 如果修改了配置文件
scp backend/src/main/resources/application-prod.yml root@www.quexitai.com:/opt/easy-joy-life/backend/src/main/resources/
```

**步骤2: 执行更新脚本**
```bash
ssh root@www.quexitai.com "cd /opt/easy-joy-life/deploy && chmod +x update-backend-only.sh && ./update-backend-only.sh"
```

### 服务器操作

```bash
# SSH到服务器
ssh root@www.quexitai.com

# 执行更新脚本
cd /opt/easy-joy-life/deploy
chmod +x update-backend-only.sh
./update-backend-only.sh
```

---

## 📝 更新流程说明

### update-backend-only.sh 做了什么？

1. ✅ **构建应用** - 编译Java代码，打包JAR文件
2. ✅ **重启服务** - 仅重启Spring Boot服务
3. ✅ **健康检查** - 验证服务是否正常启动
4. ✅ **API测试** - 测试接口是否可访问

### 不会做什么？

- ❌ 不会重启MySQL
- ❌ 不会重启Redis
- ❌ 不会重启Nginx
- ❌ 不会修改数据库

## 🔧 其他更新场景

### 1. 仅更新Nginx配置

```bash
# 修改配置后重新加载（不中断服务）
sudo nginx -t                    # 测试配置
sudo systemctl reload nginx      # 重新加载配置

# 或者重启Nginx
sudo systemctl restart nginx
```

### 2. 更新数据库结构

```bash
# 执行SQL脚本
mysql --defaults-file=/etc/mysql/debian.cnf -D easy_joy_life_db < your-update.sql
```

### 3. 更新前端小程序

小程序代码在本地开发，通过微信开发者工具上传，不需要服务器操作。


## ⏱️ 更新时间对比

| 更新方式 | 耗时 | 影响范围 |
|---------|------|---------|
| **仅更新Spring Boot** | ~30秒 | 仅后端API短暂不可用 |
| **全量部署** | ~2分钟 | 所有服务重启 |
| **仅重启服务** | ~10秒 | 仅后端API短暂不可用 |
| **重新加载Nginx** | ~1秒 | 无影响 |

## 🔍 故障排查

### 更新后服务启动失败

```bash
# 查看详细日志
journalctl -u easy-joy-life-backend -n 200 --no-pager

# 查看错误信息
journalctl -u easy-joy-life-backend -p err --no-pager

# 检查JAR文件
ls -lh /opt/easy-joy-life/backend/target/easy-joy-life-system-1.0.0.jar
```

### 更新后API访问失败

```bash
# 检查服务状态
systemctl status easy-joy-life-backend

# 检查端口监听
netstat -tuln | grep 8080

# 测试本地API
curl http://localhost:8080/api/stores

# 测试线上API
curl https://www.quexitai.com/api/stores
```

### 回滚到上一个版本

```bash
# 如果有备份的JAR文件
cp /opt/easy-joy-life/backend/target/easy-joy-life-system-1.0.0.jar.backup \
   /opt/easy-joy-life/backend/target/easy-joy-life-system-1.0.0.jar

# 重启服务
systemctl restart easy-joy-life-backend
```

## 💡 最佳实践

1. **更新前备份**
   ```bash
   cp /opt/easy-joy-life/backend/target/easy-joy-life-system-1.0.0.jar \
      /opt/easy-joy-life/backend/target/easy-joy-life-system-1.0.0.jar.backup
   ```

2. **测试后再更新**
   - 在本地或测试环境先测试
   - 确认功能正常后再更新生产环境

3. **查看日志**
   - 更新后立即查看日志
   - 确认没有错误信息

4. **监控服务**
   - 更新后监控服务运行状态
   - 确认API响应正常

5. **避免高峰期更新**
   - 选择用户较少的时间段更新
   - 减少对用户的影响
