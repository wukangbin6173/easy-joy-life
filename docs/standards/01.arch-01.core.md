## 🎯 设计哲学

### 1. 微信生态优先

**核心理念**：深度集成微信生态，提供无缝用户体验

- 使用微信小程序作为唯一前端入口
- 利用微信支付作为唯一支付方式
- 通过微信用户体系实现快速登录

**优势**：
- ✅ 用户无需额外注册
- ✅ 支付流程简单可靠
- ✅ 降低用户使用门槛

### 2. 无人值守设计

**核心理念**：系统自动化运营，减少人工干预

```
用户扫码 → 自动开门 → 自动计时 → 自动扣费 → 自动结算
```

**关键特性**：
- 自动化业务流程
- 实时状态监控
- 异常自动告警
- 远程设备控制

### 3. 前后端分离

**架构模式**：
```
微信小程序（前端）
        ↓ HTTPS/JSON
Spring Boot（后端 API）
        ↓
MySQL + Redis
```

**接口规范**：
- RESTful API 设计
- 统一的响应格式
- JWT Token 认证
- 完善的错误处理

## 🏗️ 技术架构

## 🔐 安全原则

### 1. 认证授权

- **微信登录**：使用微信官方 code2Session 接口
- **Token 管理**：JWT Token，有效期 7 天
- **权限控制**：基于角色的访问控制（RBAC）

### 2. 数据安全

- **敏感信息加密**：用户手机号、支付信息
- **HTTPS 传输**：所有 API 必须使用 HTTPS
- **SQL 注入防护**：使用 MyBatis 参数化查询

### 3. 支付安全

- **证书管理**：微信支付 API 证书定期更新
- **签名验证**：所有支付回调必须验证签名
- **幂等性保证**：支付订单防重复提交

## 📊 数据设计原则

### 1. 核心实体

```
用户（User）
  ↓ 1:N
订单（Order）
  ↓ 1:1
支付记录（Payment）

门店（Store）
  ↓ 1:N
房间（Room）
  ↓ 1:N
设备（Device）
```

### 2. 状态管理

**订单状态流转**：
```
待支付 → 已支付 → 使用中 → 已完成 → 已取消
```

**房间状态**：
```
空闲 → 占用中 → 维护中
```

### 3. 数据一致性

- **事务保证**：订单创建、支付、开门必须在同一事务
- **分布式锁**：使用 Redis 实现房间预订锁
- **最终一致性**：支付回调异步处理，保证最终一致

## 🚀 性能优化原则

### 1. 缓存策略

| 数据类型 | 缓存时间 | 更新策略 |
|---------|---------|---------|
| 门店列表 | 1 小时 | 主动更新 |
| 房间状态 | 5 分钟 | 实时更新 |
| 用户信息 | 30 分钟 | 被动失效 |

### 2. 数据库优化

- **索引设计**：为常用查询字段建立索引
- **分页查询**：列表接口必须分页
- **慢查询监控**：记录超过 1 秒的查询

### 3. 接口优化

- **响应压缩**：启用 Gzip 压缩
- **接口限流**：防止恶意请求
- **异步处理**：耗时操作异步执行

---

## 🛡️ 容错设计

### 1. 降级策略

- **支付降级**：支付失败时提供重试机制
- **设备降级**：设备离线时提供人工开门码
- **缓存降级**：Redis 故障时直接查询数据库

### 2. 监控告警

- **业务监控**：订单异常、支付失败
- **系统监控**：CPU、内存、磁盘
- **日志监控**：错误日志实时告警

### 3. 数据备份

- **数据库备份**：每日全量备份
- **日志备份**：保留 30 天日志
- **配置备份**：版本控制管理
