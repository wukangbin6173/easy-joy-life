## 🔍 完整检查（详细）

### 方法2: 使用完整检查脚本

```bash

```

- ✅ Nginx服务状态、配置、端口监听
- ✅ MySQL容器状态、数据库连接、表数量
- ✅ Redis容器状态、连接测试、缓存键数量
- ✅ Spring Boot容器状态、健康检查、重启次数
- ✅ 代码版本对比（本地 vs 远程）
- ✅ JAR文件构建时间
- ✅ 网络连通性测试
- ✅ SSL证书有效期
- ✅ Docker网络状态

## 🔧 手动检查命令

### 1. 检查所有Docker容器

```bash
docker ps
```

**期望输出：**
```

abc123def456   easy-joy-life-backend    Up 2 hours     0.0.0.0:8080->8080/tcp   easy-joy-life-backend-prod
def456ghi789   mysql:8.0                Up 2 hours     0.0.0.0:3306->3306/tcp   easy-joy-life-mysql-prod
ghi789jkl012   redis:6.2-alpine         Up 2 hours     0.0.0.0:6379->6379/tcp   easy-joy-life-redis-prod
```

### 2. 检查Nginx状态

```bash
systemctl status nginx
```

### 3. 检查端口监听

```bash
netstat -tuln | grep -E ':(80|443|3306|6379|8080) '
```

**期望输出：**
```
tcp        0      0 0.0.0.0:80              0.0.0.0:*               LISTEN
tcp        0      0 0.0.0.0:443             0.0.0.0:*               LISTEN
tcp        0      0 0.0.0.0:3306            0.0.0.0:*               LISTEN
tcp        0      0 0.0.0.0:6379            0.0.0.0:*               LISTEN
tcp        0      0 0.0.0.0:8080            0.0.0.0:*               LISTEN
```

### 4. 测试API访问

```bash
# 本地测试
curl http://localhost:8080/api/stores

# HTTPS测试
curl https://www.quexitai.com/api/stores
```

### 5. 检查容器日志

```bash
# Spring Boot日志
docker logs easy-joy-life-backend-prod --tail 50

# MySQL日志
docker logs easy-joy-life-mysql-prod --tail 50

# Redis日志
docker logs easy-joy-life-redis-prod --tail 50
```

### 6. 检查代码版本

```bash
cd /opt/easy-joy-life/backend

# 查看本地提交
git log -1 --oneline

# 查看远程最新提交
git fetch origin main
git log origin/main -1 --oneline

# 比较本地和远程
git status
```

### 7. 检查JAR文件

```bash
cd /opt/easy-joy-life/backend

# 查看JAR文件信息
ls -lh target/easy-joy-life-system-1.0.0.jar

# 查看构建时间
stat target/easy-joy-life-system-1.0.0.jar
```

## 🔄 如何更新到最新版本

### 步骤1: 拉取最新代码

```bash
cd /opt/easy-joy-life
git pull origin main
```

### 步骤2: 重新构建应用

```bash
cd backend
./mvnw clean package -DskipTests -Pprod
```

### 步骤3: 重新部署

```bash
cd ../deploy
docker-compose -f docker-compose.prod.yml up -d --build backend
```

### 步骤4: 验证部署

```bash
# 等待30秒让服务启动
sleep 30

# 检查服务状态
docker ps | grep backend

# 测试API
curl https://www.quexitai.com/api/stores
```

## 🚨 常见问题排查

### 问题1: 服务未运行

**症状：** `docker ps` 看不到某个容器

**解决方案：**
```bash
cd /opt/easy-joy-life/deploy
docker-compose -f docker-compose.prod.yml up -d
```

### 问题2: 容器频繁重启

**症状：** 容器状态显示 "Restarting"

**排查步骤：**
```bash
# 查看容器日志
docker logs easy-joy-life-backend-prod --tail 100

# 检查容器状态
docker inspect easy-joy-life-backend-prod
```

### 问题3: API访问失败

**症状：** `curl https://www.quexitai.com/api/stores` 返回错误

**排查步骤：**
```bash
# 1. 检查Nginx
systemctl status nginx
nginx -t

# 2. 检查后端服务
curl http://localhost:8080/api/stores

# 3. 检查防火墙
ufw status

# 4. 检查SSL证书
certbot certificates
```

### 问题4: 数据库连接失败

**症状：** 后端日志显示数据库连接错误

**排查步骤：**
```bash
# 1. 检查MySQL容器
docker ps | grep mysql

# 2. 测试数据库连接
docker exec easy-joy-life-mysql-prod mysqladmin ping

# 3. 检查数据库配置
docker exec easy-joy-life-mysql-prod mysql -e "SHOW DATABASES;"
```

### 问题5: 版本不是最新

**症状：** 本地代码落后于远程仓库

**解决方案：**
```bash
# 1. 备份当前版本
cd /opt/easy-joy-life
git stash

# 2. 拉取最新代码
git pull origin main

# 3. 重新构建和部署
cd backend
./mvnw clean package -DskipTests -Pprod
cd ../deploy
docker-compose -f docker-compose.prod.yml up -d --build backend
```

## 📊 服务监控建议

### 定期检查（每天）

```bash
# 添加到crontab
crontab -e

# 每天早上9点检查服务状态
0 9 * * * /opt/easy-joy-life/deploy/quick-status-check.sh > /var/log/service-check.log 2>&1
```

### 实时监控

```bash
# 实时查看容器状态
watch -n 5 'docker ps'

# 实时查看日志
docker-compose -f docker-compose.prod.yml logs -f
```

## 📞 获取帮助

如果遇到问题：

1. 查看完整日志：`docker-compose -f docker-compose.prod.yml logs`
2. 检查系统资源：`htop` 或 `free -h`
3. 查看磁盘空间：`df -h`
4. 重启所有服务：`docker-compose -f docker-compose.prod.yml restart`

## ✅ 健康服务的标准

所有服务正常运行时应该满足：

- ✅ 4个服务进程全部运行（Nginx + MySQL + Redis + Spring Boot）
- ✅ 所有端口正常监听（80, 443, 3306, 6379, 8080）
- ✅ API可以正常访问（https://www.quexitai.com/api/stores）
- ✅ 容器重启次数为0
- ✅ 代码版本与远程仓库一致
- ✅ JAR文件构建时间晚于容器启动时间
- ✅ SSL证书有效期大于30天
- ✅ 数据库连接正常
- ✅ Redis缓存可用
